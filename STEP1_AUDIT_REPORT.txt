A. EXECUTIVE SUMMARY
================================================================================

FOUND: Venchick Trader is a Discord-based SIGNAL NOTIFICATION BOT with an AI
analyst chat layer. It connects to MetaTrader 5 exclusively for MARKET DATA
(OHLCV, spreads, indicators), runs a multi-engine signal pipeline (structure →
SMC → session → bias → second-opinion LLM), and broadcasts trade setup cards
to Discord channels. It does NOT place, modify, or close any actual trades.

The codebase is substantially complete as a signal + informational tool. Several
key architectural components required by the stated target system are absent or
incomplete, most critically: MT5 credential loading from environment variables,
actual trade execution, multi-account support, per-user drawdown protection,
and any form of testing. The project has been built in named "phases" (Phases
1–10 referenced in docstrings), and the code quality is high overall — well-
structured, defensively coded, and consistently documented.

Risk level before demo trading: HIGH. Before proceeding to Step 2, specific
issues documented in this report must be resolved.

H. STRATEGY / SIGNAL PIPELINE
================================================================================

FOUND — Complete signal generation pipeline:

TIER 1 — Base signal (mt5_engine.analyze_market_structure):
  - Fetches M15/H1/H4/D1 OHLCV data (250 candles each)
  - Computes: EMA(20/50/200), RSI(14), ATR(14), Bollinger Bands(20,2)
  - Multi-TF trend alignment via EMA stack (+1 bull / -1 bear / 0 mixed)
  - Swing high/low from most recent 60 H4 bars
  - Signal conditions (requires >=3/4 TF alignment):
      BUY : Mean Reversion (bounce at support, RSI<55)
            Breakout (above prior swing high)
            Momentum (aligned uptrend, RSI>50, not overbought)
      SELL: Mirror of above
  - Levels: entry = current price
            SL    = +/- 1.5 x ATR
            TP1/2/3 = 1:1 / 2:1 / 3:1 risk-reward
  - Confidence = (aligned_count / 4) x 100%

TIER 2 — Confluence filter (bias_engine.evaluate_xauusd_bias_and_scenarios):
  - structure_engine : BOS/CHOCH on D1/H4/H1/M15, trend bias, premium/discount
  - smc_engine       : active BSL/SSL, equal H/L, sweeps, FVGs, order blocks
  - session_engine   : session clock, PDH/PDL/PWH/PWL/PMH/PML, ASH/ASL
  - news_engine      : freeze window, killswitch, upcoming high-impact events
  - Computes overall_bias (STRONG_BULLISH / BULLISH / NEUTRAL / BEARISH /
    STRONG_BEARISH) and confluence_score (1-5)
  - Builds conditional scenarios:
      BULLISH_CONTINUATION: bullish bias + discount zone + near bullish OB/FVG
      BEARISH_CONTINUATION: mirror
      LIQUIDITY_RAID_REVERSAL: sweep of PDH/PDL/PWH/PWL + M15 CHOCH opposing
  - Filter gates:
      base model direction must agree with overall_bias
      AND confluence_score >= MIN_CONFLUENCE_SCORE (3/5)
      AND at least 1 active scenario must exist
  - Blended confidence: (base_confidence + confluence_score/5*100) / 2

TIER 3 — Second opinion filter (second_opinion_engine.get_second_opinion):
  - LLM (Llama 3.3 70B) receives: signal levels, bias context, news overlay,
    recent alert history for this symbol
  - LLM can ONLY: veto (proceed=false) or reduce confidence (-20 to 0)
  - Strict JSON output, fallback=proceed on any failure, 8s timeout

RESULT: Signal broadcast to Discord channels
  - Under-$200 channel (always)
  - Over-$200 channel (always)
  - High-winrate channel (if confidence >= 75%)
  - Private rooms (on account join / via news delivery)

  PWH/PWL  = Prior W1 candle high/low
  PMH/PML  = Prior MN1 candle high/low
  ASH/ASL  = Today's Asian session high/low from M15 data

Asian range sweep detection: ICT "Judas Swing" — checks if post-Asian-close
  price trades beyond ASH (ash_swept) or ASL (asl_swept) during London/NY.

Effect on trading: Informs bias_engine confluence score and scenario triggers;
  provides AI context. Sessions are not hard gates in the signal scanner.

SECURITY ISSUES FOUND:

Issue 1 — MT5 Credentials Not Loaded (Severity: HIGH)
  FILE     : mt5_engine.py
  LOCATION : MT5_CONFIG dict (lines 33-39)
  ISSUE    : MT5_CONFIG has all None values. No env-var loading exists.
             The bot connects to the already-running MT5 terminal without
             logging in programmatically. If the terminal is logged out,
             the bot silently fails to connect with no clear error about
             missing credentials.
  FIX      : Add os.getenv("MT5_LOGIN"), os.getenv("MT5_PASSWORD"),
             os.getenv("MT5_SERVER") loading into MT5_CONFIG at module
             startup, with validation before init_mt5() is called.

Issue 2 — No AI Response Timeout for Chat (Severity: MEDIUM)
  FILE     : ai_engine.py
  LOCATION : generate_ai_response() -> client.chat.completions.create()
  ISSUE    : No asyncio.wait_for() timeout wraps the Groq chat call.
             If Groq is slow, the on_message handler will stall indefinitely,
             potentially blocking the Discord event loop.
  FIX      : Wrap with asyncio.wait_for(..., timeout=30.0)

Issue 3 — news_engine calls load_dotenv() at module import level (Severity: LOW)
  FILE     : news_engine.py
  LOCATION : Lines 78-79 (module scope)
  ISSUE    : Any import of news_engine immediately loads .env into os.environ.
             Not a security issue per se, but surprising and breaks test isolation.
  FIX      : Move load_dotenv() to main.py only.

Issue 4 — Negative balance allowed with admin confirm=True (Severity: LOW)
  FILE     : main.py
  LOCATION : deductbalance command
  ISSUE    : Admin can set balance to a negative number, causing incorrect
             lot sizing (negative risk -> negative lots).
  FIX      : Add floor check in _send_private_welcome_signals or calculate_lot_size.

P. CONCURRENCY / ASYNC ANALYSIS
================================================================================

Async framework    : asyncio (single-threaded event loop)
Background loops   : discord.ext.tasks (3 loops: 10s, 5s, 60s)
Thread executor    : MT5 blocking calls offloaded via loop.run_in_executor()

CONCURRENCY ISSUES:

Issue 1 — Shared mutable state without locks (Severity: MEDIUM)
  LOCATION : main.py — SIGNAL_MESSAGES dict, SIGNAL_THREADS dict,
             _last_killswitch_state bool
  ISSUE    : Mutated by both signal_scanner_loop and price_ticker_loop.
             Safe in practice (asyncio is cooperative, not preemptive), but
             fragile by design. Thread executors do not write to these dicts,
             so no actual race condition currently exists.
  FIX      : Document the single-threaded assumption clearly.

Issue 2 — asyncio.create_task fire-and-forget (Severity: LOW)
  LOCATION : ai_engine.py generate_ai_response()
  ISSUE    : Untracked tasks can be garbage collected before completing
             if the bot restarts quickly. Acceptable for logging.
  FIX      : Acceptable as designed; already documented in code.

Issue 3 — No duplicate order protection for future trade execution (Severity: LOW)
  ISSUE    : When trade execution is added later, the "no duplicate signals
             per pair" check (active_pairs set) provides some protection but
             runs inside signal_scanner_loop only. A restart between the check
             and the DB write could allow two signals for the same pair.
  FIX      : When adding trade execution, add DB-level uniqueness constraint
             on (pair, status='ACTIVE').
